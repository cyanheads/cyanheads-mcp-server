# 0.1.6 — 2026-05-28

## Changed

- **`TransformersEmbeddingsRuntime` lazy-loads the feature-extraction pipeline.** Model load is deferred from `CatalogService.initialize()` to the first `embedQuery()` call. Concurrent first-callers share a single in-flight load promise; on failure the promise is cleared so the next call retries from scratch. Startup latency drops by the model warm-up cost (measured ~2 s warm-disk, ~15 s cold-disk in the production container); the cost moves to the first `cyanheads_search` call and is amortized across the lifetime of the process.

- **`IEmbeddingsRuntime` interface tightened.** Public `initialize()` removed — the runtime is responsible for its own lazy-load and callers only see `modelId` + `embedQuery()`. Internal interface; no impact on npm consumers or tool authors. `CatalogService.initialize()` no longer awaits an embedding runtime warm-up step.

- **Idle memory profile.** Containers serving fewer than one `cyanheads_search` per process hold ~150–200 MB resident instead of ~710 MB. Once any query runs, the loaded pipeline stays warm and resident through process death (no eviction).
