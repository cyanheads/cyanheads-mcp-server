# 0.1.7 — 2026-05-28

## Fixed

- **First `cyanheads_search` after a fresh container fails with `Unable to get model file path or buffer`.** The 0.1.6 lazy-load path triggered `pipeline()` inside a request handler. With `@opentelemetry/instrumentation-http` active, the wrapped fetch path can't complete the model download on a cold cache; the same call from `CatalogService.initialize()` (setup context) succeeds. Fix: `CatalogService.initialize()` fires a fire-and-forget `embedQuery('warmup', …)` after building the index. The model loads in the background during the seconds before any user query arrives; the first real query joins the in-flight `_loadPromise` instead of starting a fresh load.

## Changed

- **Startup still does not block on model load.** The warm-up is fire-and-forget — `CatalogService.initialize()` returns as soon as the index is built. Server startup latency unchanged from 0.1.6 (~150–200 MB resident, transport listening within ~100 ms of process start). The model load runs concurrently and is typically ready before the first user query.
- **Warm-up failure is non-fatal.** If the background `embedQuery('warmup', …)` rejects, the rejection is logged at `warning` and swallowed. `_loadPromise` is cleared (per the 0.1.6 retry semantics), so the first real `cyanheads_search` retries from scratch.
