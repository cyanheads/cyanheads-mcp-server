# 0.1.8 — 2026-05-28

## Fixed

- **0.1.7 `Background embedding warm-up failed` on every cold-cache deploy.** The fire-and-forget `void embedQuery('warmup', …)` yielded to the microtask queue before transformers.js could run its model fetch, and by the time `pipeline()` actually executed, `@opentelemetry/instrumentation-http` had already monkey-patched fetch. The wrapped fetch can't complete the HF Hub download on a cold cache (returns `Unable to get model file path or buffer`). Once the warm-up failed, the first user `cyanheads_search` retried from request-handler context and failed identically. Fix: `await` the warm-up, keeping `pipeline()` inside the pre-OTEL window where it succeeds.

## Changed

- **Server startup blocks on model warm-up again.** Effectively the 0.1.5 startup profile: ~2 s on warm disk, ~15 s on cold disk, ~710 MB resident before transport listens. The 0.1.6 lazy-no-evict idea is sound in isolation but conflicts with the current `@cyanheads/mcp-ts-core` OTEL setup order. A framework-level fix (delay HTTP instrumentation registration, or scope it to the MCP endpoint) would let lazy-load work; tracked separately.
