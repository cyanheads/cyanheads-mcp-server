# 0.5.1 — 2026-11-16

## Added

- **`composesWith`** on `cyanheads_describe_entry` results for servers and tools: the servers the maintainer says compose with the owning server, plus a `## Composes with` list in `content[]` ([#40](https://github.com/cyanheads/cyanheads-mcp-server/issues/40)).
- **`cyanheads_search_catalog` lists entries when `query` is omitted** (or `null` or `""`), in name order, optionally filtered by `category`, with no `score` or `effectiveQuery` ([#41](https://github.com/cyanheads/cyanheads-mcp-server/issues/41)).
- **`CATALOG_CLAMP_LIMITS`** (default `true`): `false` advertises and enforces `maximum: 1000` on `limit` instead of serving a larger value at 1000 ([#39](https://github.com/cyanheads/cyanheads-mcp-server/issues/39)).

## Changed

- **`cyanheads_search_catalog` serves up to 1000 results per call**, up from 20. A larger `limit` is served at 1000, with a notice and `nextOffset` when more matches follow, and increments the `mcp.input.count_clamped` counter ([#39](https://github.com/cyanheads/cyanheads-mcp-server/issues/39)).
- **`cyanheads-guide` skill 1.1**: § Identifiers says a server stem resolves, and new gates cover listing by omitting `query` and reading `composesWith`.

## Fixed

- **`cyanheads_describe_entry` resolves a server stem** (`pubmed` → `pubmed-mcp-server`, `cyanheads` → this server), including in the `server` input. `not_found` names the kind searched and, when the other kind has the name, that match and the `kind` to set ([#38](https://github.com/cyanheads/cyanheads-mcp-server/issues/38)).
- **`scope: ""` reads as the default** (`tools`) instead of being rejected ([#42](https://github.com/cyanheads/cyanheads-mcp-server/issues/42)).
- **The `servers` roll-up** describes each server from the catalog snapshot that scored its rows; a background catalog refresh during a search could blank a row's `brief` and report its category as `utility`.
- **The `brief` field description** now says it carries the full catalog description, not a one-line summary.
