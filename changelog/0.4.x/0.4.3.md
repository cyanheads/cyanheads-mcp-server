# 0.4.3 — 2026-09-30

## Changed

- **Docker builds** install target-platform dependencies on the native builder with Bun `1.4.0 → 1.4.2`; OpenTelemetry peers use the framework's tested ranges, security scanner, and release-age policy. Runtime logging follows framework configuration.
- **Development tooling** synchronizes framework skills and checks for definition import failures, bundle/version alignment, Docker build platforms, skill versions, and release annotations. Publishing uses a gated release PR.
- **Documentation and packaging** describe current catalog behavior, failure-payload logging, and OTLP logs configuration; correct the VS Code install link and exclude runtime logs and nested bundles from distribution artifacts.

## Fixed

- **Search queries** reject whitespace-only input before embedding and trim valid queries for embedding and echo, retaining the 500-character raw limit. ([#12](https://github.com/cyanheads/cyanheads-mcp-server/issues/12))
- **Search continuation** exposes independent result and server roll-up offsets, full totals, and nullable next offsets. Reuse the query and filters; pages reflect the current catalog. ([#13](https://github.com/cyanheads/cyanheads-mcp-server/issues/13))
- **Catalog normalization** collapses identical exact-name duplicates before indexing and rejects conflicting records; search, descriptions, counts, and vectors share the normalized inventory. ([#14](https://github.com/cyanheads/cyanheads-mcp-server/issues/14))
- **Literal rendering** preserves descriptions, identifiers, metadata, and install payloads through Markdown rendering with delimiter-sized code spans and blocks. ([#15](https://github.com/cyanheads/cyanheads-mcp-server/issues/15))
- **Tool installation handoffs** include owning-server connection metadata and client-filtered snippets. Local-only curl requests return actionable stdio guidance, with required environment variables visible even when no snippet applies. ([#16](https://github.com/cyanheads/cyanheads-mcp-server/issues/16))
- **Empty catalogs** fail startup validation and retain the previous index on refresh; nonempty catalogs with zero-tool servers remain valid. ([#17](https://github.com/cyanheads/cyanheads-mcp-server/issues/17))
- **Name resolution** prefers exact remote names, then unique case-insensitive matches, and returns canonical names. Ambiguous folds remain unresolved; remote entries take precedence over self records. ([#20](https://github.com/cyanheads/cyanheads-mcp-server/issues/20))
- **Error recovery** uses framework-populated contract hints for handler and service failures, including retryable `catalog_empty` responses.
