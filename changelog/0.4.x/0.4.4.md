# 0.4.4 — 2026-10-18

## Changed

- **`cyanheads_search_catalog` `limit`** accepts 1–1000 and serves at most 20 results per call. When a larger `limit` leaves matches past the page, the response adds optional `truncated`, `shown`, and `cap` fields and a `notice` naming the offset to continue from. ([#29](https://github.com/cyanheads/cyanheads-mcp-server/issues/29))
- **Docker builds** use Bun `1.4.2 → 1.4.3` and delete musl-only packages from the production image; `.dockerignore` excludes every `.env*` file and the MCP Registry token files.
- **Development tooling and framework skills** synchronized with `@cyanheads/mcp-ts-core` 0.13.15: devcheck and packaging lint, the CodeQL language matrix, and `.env.example`.
- **`server.json` packages** launch through `npx` instead of `node` with `run start:*` arguments; the HTTP package sets `MCP_TRANSPORT_TYPE=http`.
- **Documentation** covers owner-aware describe, the limit clamp, the new snippet clients, and per-client hosted install steps.

## Fixed

- **`cyanheads_describe_entry`** takes an optional `server`: a search result's `name` + `server` describes exactly that row, in either scope. A tool name owned by several servers returns `ambiguous_owner`, listing the owners, instead of resolving to the last one in catalog order. ([#24](https://github.com/cyanheads/cyanheads-mcp-server/issues/24))
- **Catalog vectors** are normalized at load, so every score is a cosine similarity even when a catalog's vectors drift from unit length; a load whose norms deviate by more than `1e-4` logs one bounded warning. Vectors with the wrong dimension, zero norm, or a non-finite component are rejected: startup fails, and a refresh keeps the previous index. ([#25](https://github.com/cyanheads/cyanheads-mcp-server/issues/25))
- **Curl snippet** sends a legacy `initialize` probe that hosted endpoints accept: `protocolVersion` `2025-11-25`, `Accept: application/json, text/event-stream`, and no `MCP-Protocol-Version` header. Hosted endpoints rejected the previous probe, which sent `MCP-Protocol-Version: 2026-07-28` with its `initialize` body and no `Accept` header. ([#23](https://github.com/cyanheads/cyanheads-mcp-server/issues/23))
- **HTTP and stdio snippets** no longer name clients that reject them: the generic remote snippet is labeled `Generic (mcpServers JSON)`, and the stdio label is `Claude Desktop / generic`. The `client` enum adds `cline` (stdio, plus a `streamableHttp` snippet for hosted servers). ([#30](https://github.com/cyanheads/cyanheads-mcp-server/issues/30))
